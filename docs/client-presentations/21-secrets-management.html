AES-256-GCM Encryption

Every secret value is encrypted at rest using AES-256-GCM — the same authenticated encryption standard used by cloud providers and financial institutions.

Encryption Properties

Property Value Purpose
Algorithm AES-256-GCM Authenticated encryption with 128-bit auth tag
Key Derivation SHA-256 Deterministic 32-byte key from any-length input
Nonce 12 bytes, cryptographically random Unique per encryption, prevents replay attacks
Output Format Base64(nonce + ciphertext) Safe for JSON, YAML, environment variables
Tamper Detection GCM authentication tag Wrong key or corrupted data fails decryption

Key Management

The encryption key is loaded from AETHER_SECRET_KEY environment variable. If not set, Aether derives a machine-specific key from hostname using SHA-256. Production deployments should always set an explicit key of at least 16 bytes. Each encryption operation generates a fresh cryptographically random nonce, so encrypting the same value twice produces different ciphertext.

AES-256-GCM provides both confidentiality and authenticity — any tampering with the ciphertext is detected on decryption, and a wrong key produces a clear error rather than garbage output.

# 1. Create a secret container
$ aether secrets create db-creds --namespace production

# 2. Set encrypted values
$ aether secrets set db-creds password "s3cure-p@ssw0rd"
$ aether secrets set db-creds username "app-user"

  Key 'password' set in 'db-creds' (version 1, AES-256-GCM)
  Key 'username' set in 'db-creds' (version 1, AES-256-GCM)

# 3. Retrieve decrypted values
$ aether secrets get db-creds password

  s3cure-p@ssw0rd

# 4. Rotate a value
$ aether secrets rotate db-creds password "n3w-s3cure-p@ss"

  Key 'password' rotated in 'db-creds' (version 2)

# 5. View access audit trail
$ aether secrets audit db-creds

Version Tracking

📄

Auto-Versioning

Every set or rotate operation increments the key's version counter. This provides a clear history of how many times a secret has been updated without storing old values.

📅

Last Rotated Timestamp

Each secret value records when it was last rotated as an RFC 3339 timestamp. This timestamp drives the rotation policy engine and expiry alerting system.

Rotation Policies

Enforce automatic rotation schedules and expiry alerts. Every secret is created with a default rotation policy that can be customized per use case.

Default Rotation Policy

Parameter Default Value Description
interval_days 90 Rotate every 90 days for compliance
max_age_days 365 Force rotation after 1 year regardless
notify_before_days 14 Alert 14 days before max age expiry

Rotation Audit

$ aether secrets rotation-audit

[CRITICAL] Key 'api-key' in 'stripe-creds' is 400 days old (max: 365)
[WARNING]  Key 'password' in 'db-creds' expires in 12 days
[OK]       Key 'token' in 'github-creds' rotated 15 days ago (next: 75 days)

Policy Validation

Rotation policies are validated on creation to prevent misconfiguration:

  • interval_days must be greater than 0
  • max_age_days must be greater than or equal to interval_days
  • notify_before_days must be less than or equal to max_age_days

This prevents impossible policies like "notify 400 days before a 365-day expiry" that would cause constant false-positive alerts.

🔔

Warning Alerts

When a secret's age exceeds max_age_days - notify_before_days, Aether emits a WARNING alert. This gives teams a 14-day window (by default) to plan rotation.

🚨

Critical Alerts

When a secret exceeds max_age_days, the alert escalates to CRITICAL. The secret is overdue for rotation and may violate compliance requirements.

Access Audit Trail

Every secret operation is logged with actor identity, action type, key name, and timestamp. The audit trail provides complete visibility into who accessed what and when.

Tracked Actions

Action Trigger Logged Data
READ aether secrets get Actor, secret name, key, timestamp
WRITE aether secrets set Actor, secret name, key, version, timestamp
DELETE aether secrets delete-key Actor, secret name, key, timestamp
ROTATE aether secrets rotate Actor, secret name, key, new version, timestamp
