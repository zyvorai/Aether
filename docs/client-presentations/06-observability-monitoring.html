Prometheus Metrics

Aether exposes a /metrics endpoint in Prometheus format. Scrape it directly or use the built-in dashboard.

📊

Export Metrics

Start the metrics server on the default port and point Prometheus at it.

$ aether metrics --port 9090

Metrics server listening on :9090
  Endpoint: /metrics
  Format:   Prometheus text/plain

# Scrape config (prometheus.yml)
scrape_configs:
  - job_name: 'aether'
    static_configs:
      - targets: ['localhost:9090']

Circuit Breaker Protection

Aether automatically applies circuit breaker logic to prevent cascading failures.

Circuit Breaker States

  • Closed — Normal operation, requests pass through
  • Open — Failures exceeded threshold, requests blocked for cooldown
  • Half-Open — Probe requests sent to test recovery
$ aether health my-web-app --circuit-breaker
State: CLOSED
  Failures: 0/3 threshold
  Success rate: 100% (last 100 checks)
  Last trip: 6d ago (auto-recovered)

Webhook Notifications

Configure Webhooks

$ aether notify add \
    --name ops-slack \
    --type webhook \
    --url https://hooks.slack.com/T0/B0/xxx \
    --events "critical,fatal" \
    --retry-count 3 \
    --retry-delay 10s

Webhook registered:
  Name:    ops-slack
  Events:  critical, fatal
  Retries: 3 (10s delay)
  Queue:   persistent (survives restart)

Set Up Monitoring Now

From zero to full observability in three commands.

1

Start the metrics server

Expose Prometheus metrics on port 9090 and configure your scrape target.

2

Import the Grafana dashboard

Export the pre-built 14-panel dashboard and import it into your Grafana instance.

3

Configure webhook alerts

Add Slack, PagerDuty, or email endpoints for critical and fatal events.

# Complete setup in 3 commands
$ aether metrics --port 9090 --daemon
$ aether metrics dashboard --export grafana > dashboard.json

    --url https://hooks.slack.com/T0/B0/xxx \
