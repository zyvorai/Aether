Write it once.

One aether/v1 file says what to build, what it needs, and where it is allowed to run.

workload.yaml
apiVersion: aether/v1
kind: Workload
metadata:
  name: demo-webserver
  owner: team
  project: demo
build:
  context: "."
  dockerfile: Dockerfile
  registry: localhost
requirements:
  cpu: "500m"
  memory: 256Mi
  storage: 1Gi
runtime:
  preferred: auto
  allow: [container, kube, kubevirt]
network:
  service: true
  ports:
    - containerPort: 8080
      servicePort: 80

  • Podman

    Containers on one host: laptops, edge machines and CI runners. A Docker adapter is included too.

  • Kubernetes

    Cluster workloads with services, ingress and autoscaling.

  • KubeVirt

    Virtual machines on Kubernetes, for isolation, GPUs and live migration.

Ask why.

Aether scores each runtime you allow, and shows the reasons and warnings behind every score.

  • 30%

    Cost

    What this size of workload costs to run there.

  • 30%

    Performance

    How CPU, memory and GPU needs fit.

  • 25%

    Reliability

    Health, restarts and isolation.

  • 15%

    Availability

    High availability, scaling and uptime profile.

aether --spec workload.yaml decide --explain

Default weights shown; they are yours to change, and an intent: block shifts them. It is a rule-based estimate from your spec, not a benchmark: pass --runtime and that is where it goes. How scoring works

Then move it.

Change runtime with one command and pick how careful to be.

aether migrate demo-webserver kubevirt --strategy blue-green

  • Immediate

    Stop the source, start the target, check it. Restarts the source if the target fails.

  • Blue-green Default

    Start the target while the source runs. Check it, wait up to 30 seconds, then remove the source.

  • Rolling

    Start the target, retry its health check, then step to 100% with a check at each step.

  • Canary

    Check the target at 10, 25, 50, 75 and 100 percent. Remove it if a step fails.

What a migration does not move

Volume data, databases, IP addresses and DNS stay where they are. The percentages are health-gated steps: Aether does not split live traffic between runtimes. Read the limits

Moving a KubeVirt VM to another node instead? aether live-migrate does that, for specs that enable it.

The same control plane and the same state, wherever you work.

    aether run
